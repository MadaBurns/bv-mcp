### Changed

- OAuth: the Enterprise Managed Auth JWKS helper (`src/oauth/jwks.ts`) is hardened. Concurrent lookups of the same `jwks_uri` in one isolate now share a single outbound fetch, so a burst of tokens carrying an unknown `kid` can no longer drive one IdP request each (the KV once-per-60s marker stays as the cross-isolate, best-effort layer). A 200 response whose `keys` holds no usable public RS256/ES256 key (for example `{"keys":[{}]}`) is now a failed fetch and is never cached. A JWK whose `key_ops` omits `verify` is no longer a signing candidate, and the same JWK listed twice counts once (two different keys under one `kid` are still ambiguous). When a forced refresh fails and a valid cached set exists, the cached set is returned instead of an error.
