### Fixed

- `bv-ct-index` sidecar: a compaction output put that fails now fails the job before its catalog swap. After SQ-402 started writing output runs in parallel, a put that rejected while the job was not waiting on it was dropped, so the job swapped the catalog to an output whose R2 object was never written and deleted its inputs. The first put error is now kept and rethrown, the queue retries the job, and the catalog and input objects stay as they were. A scheduled event whose cron no case matches (for example after `wrangler rollback` to older code while the schedule stays `2,17,32,47 * * * *`) now logs `ct_cron_unmatched` instead of doing nothing silently. The runbook's rollback section covers it. No migration; takes effect with `npm run deploy:ct-index`.
