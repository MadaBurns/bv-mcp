### Fixed

- A recon `404` on `/osint/check` is now recorded as its own `binding_route_absent` degradation kind instead of `binding_5xx`. The standing "backend does not serve this route yet" condition stays queryable in Analytics Engine but no longer pages the service-binding degradation alert; 5xx, timeout and unavailable still alert as before.
- `check_realtime_threat_feed` no longer says "not provisioned in this deployment" when the binding is present but the backend fails. It now reports that the backend did not return a usable response (still inconclusive, never a clean result); the "not provisioned" wording is kept for an absent binding.
