### Changed

- OAuth `jwt-bearer` (Enterprise Managed Auth) rate limiting: these exchanges no longer share the 30/min per-IP `/oauth/token` bucket, because every claude.ai exchange for every tenant arrives from Anthropic's small egress range. A request from a known client IP is limited per (IP, claimed issuer) at 120/min, with a 600/min per-IP ceiling across issuers as the abuse backstop; an unknown IP (no `cf-connecting-ip`) keeps the shared bucket and is not rejected. The 429 and 503 bodies are unchanged. Every other grant, including malformed or oversize bodies, is still gated by the shared bucket before any response.
- OAuth `jwt-bearer` rejections of an unknown, disabled or lapsed tenant (or a stale issuer index entry) now all return `invalid_grant` with the single description `Assertion not accepted`, so the error text cannot be used to enumerate which issuers are trusted or lapsed.
- `/internal/oauth/grants` now also requires the requested `redirect_uri` to pass the redirect policy that `/oauth/authorize` applies (400 `invalid_redirect_uri`), not only to match the client's registered URIs.
