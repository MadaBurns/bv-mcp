### Fixed

- An opaque API key whose entitlement lookup could not be answered (backend error, timeout, 5xx or unreadable response) now gets a retryable `503` with `Retry-After: 5`, the same response the OAuth storage-outage path already gives, instead of a `401` that made clients discard a good key. The request is still refused at every tier, no stale entitlement is served, and the outage is never cached, so the key authenticates as soon as validation recovers. A definitive "invalid key" answer is still a `401`.
