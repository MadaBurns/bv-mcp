### Fixed

- Opaque API-key validation against the entitlement backend: a backend answer of 401, 403, 404, 408 or 429 describes the backend or the internal channel, not the customer key, so it is now treated as an outage (503 with Retry-After, nothing cached, no request served) instead of a plain 401. The only definitive "no entitlement" answer remains a successful response carrying `tier: null`; any other rejecting status still yields 401. Each outage now also writes one structured `validate_key_unavailable` warning carrying only a fixed reason token (status class, timeout, fetch error or malformed body), so an outage is visible beyond 503 counts.
