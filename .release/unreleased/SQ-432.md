### Security

- OAuth CIMD hardening (SQ-421 F1/F2/F3/F5). A CIMD `client_id` with an explicit port (for example `https://host:8443/x`) is no longer CIMD-shaped, closing a port oracle against public hosts. Metadata fetches caused by a cache miss are limited to 10 per client IP per 60 s on `/oauth/authorize` (GET and POST); an exceeded or unavailable limiter answers "Unknown client_id" without fetching, and cache hits are never limited. A failed fetch is negatively cached for 60 s (`oauth:cimd-neg:<sha256>`), so a hostile `client_id` cannot drive one outbound request per call. `getClient` no longer builds a KV key for a `client_id` over 200 characters (a 512-character id previously reached a 512-byte key limit and answered 503; it now resolves or denies cleanly). CIMD cache records moved from `oauth:client:cimd:<sha256>` to `oauth:cimd:<sha256>`, outside the keyspace `getClient` reads, so `client_id=cimd:<sha256>` can no longer address a cached record.
- SQ-421 F5 (behavior note): the RFC 8252 port-agnostic loopback redirect match (`localhost` and `127.0.0.1` ignore the port) now applies to Dynamic-Client-Registration clients as well as CIMD clients, because all clients share `redirectUriMatches`.
