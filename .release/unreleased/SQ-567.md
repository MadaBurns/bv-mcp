title: scan_domain cache no longer shares a result between probe-eligible and anonymous callers
bump: patch

### Fixed

- The scan-level cache key (and the per-check in-flight key) now carries a `:tls-probe` segment when the caller's tier is probe-eligible AND the TLS probe binding is bound. The binding changes the `ssl` check's metadata and the `dane_https` finding metadata for those callers, so an anonymous caller is no longer served a result computed for a paid tier within the 5-minute TTL, and the reverse. Deployments without the binding, and anonymous traffic, keep their existing key and hit rate. No score, grade, TTL or tool output field changes. `analyze_drift` with a cached baseline reads the same partitioned key.
