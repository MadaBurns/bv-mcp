### Added

- Optional origin signatures for brand-audit watch webhooks sent to caller-supplied URLs. When the new optional Worker secret `WATCH_WEBHOOK_SIGNING_SECRET` is set (32+ bytes, distinct from every other security secret), each delivery carries `X-Blackveil-Signature: t=<unix seconds>,v1=<hex>`, an HMAC-SHA256 over `<t>.<exact body bytes>` keyed by a per-watch secret derived from the server secret and the watch id. Nothing is stored per watch and there is no schema change.
- `register_brand_audit_watch` returns that per-watch secret once, as `signingSecret`, for a watch with a `webhook_url`. `list_brand_audit_watches` never returns it. Watches registered before the secret was set are signed too once it is set; their owners re-register to obtain the secret.
- Receiver verification steps and the operator enable step are in `docs/design/brand-audit-watch-webhook.md`.

### Release boundaries

- With the secret unset, empty or failing the strength rule, behaviour is unchanged: no header, no `signingSecret` in the registration result. The first-party Brand Drift receiver path is not signed.
- No tool is added, removed or renamed and no argument changes. Enabling signing is an operator `wrangler secret put`; the secret is not required to deploy.
