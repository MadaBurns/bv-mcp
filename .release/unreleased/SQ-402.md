### Changed

- `bv-ct-index` sidecar: a lookup now opens only the runs that hold its page. The reader merges runs lazily, reading a run's next block only once the block index says it could hold the next key, so a 50-name page of `amazonaws.com` no longer reads every one of its ~6,000 overlapping runs. Rows, truncation and cursors are unchanged. Compaction keeps fewer runs live for reads to open: the planner now runs every 15 minutes (cron `2,17,32,47 * * * *`) and compacts tier 0 in 15-minute windows instead of hourly, an hourly roll-up merges each key range's tier-1 runs from earlier in the day into one, and a job writes its output runs up to six at a time. A new `ct_compaction_job_done` log line reports each job's output count, put time and duration. No migration; the cron change takes effect with `npm run deploy:ct-index`. The sidecar is still not bound to bv-mcp, so nothing changes for `discover_subdomains` yet.
