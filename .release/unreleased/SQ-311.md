### Fixed

- `check_subdomain_takeover`: every result now states its sweep denominator (#1201, #973, #948). A `SweepDescriptor` — `sweptCount`, `sweepSource: 'caller' | 'builtin'`, and when they apply `requestedCount`, `truncatedTo` (the 1000-name cap cut the caller list) and `aRecordVectorSampledTo` (the scan-path A/AAAA-vector sample cap) — is stamped on the clean finding, the #948 abstention, every dangling/fingerprint finding, and the Worker wrapper's cut-probe note. The clean prose reads "among the N subdomains swept (caller-supplied|built-in list)" and says when the list was truncated. A caller list cut by the cap returns `partial: true` (not cached). A non-empty caller list that collapses to zero usable names now abstains (`caller_list_unusable`, `checkStatus: 'error'`, no DNS issued) instead of silently sweeping the built-in 15 names in its place; an empty array still means "no list".

Not changed, operator decision: the `/mcp` request body cap is 10,240 bytes (`MAX_REQUEST_BODY_BYTES`) while the tool schema accepts 1000 names. Measured: a `tools/call` with 498 realistic FQDNs is 20,193 bytes (1.97× the cap) and 1000 names is 40,532 bytes; only ~251 names fit, so a CT-sized enumeration is rejected 413 ("Request body too large") before the tool runs. Either raise the cap or document chunking at ~250 names per call.

Score impact: none. Severities, penalties and the clean verdict's score are unchanged; only metadata, prose, the `partial` flag on a truncated caller sweep, and the unusable-list abstention are new. Package change in `@blackveil/dns-checks` (`checks/` only): needs the dns-checks release and a bv-web-prod re-vendor.
