### Fixed

- The scan-path canary now loads the scan engine at run time instead of through a static import, so importing `src/scheduled.ts` (for example from Node-project tests) no longer drags in the whole scan graph and its Durable Object module. Behaviour on the cron is unchanged; an engine that fails to load is reported as a `threw` canary outcome. Specs that simulate scheduler ticks with the alert webhook and analytics credentials set now disable the canary (`SCAN_CANARY_ENABLED=false`) so they no longer run a real scan per tick.
