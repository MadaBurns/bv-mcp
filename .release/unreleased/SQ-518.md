### Fixed

- bv-ct-index sidecar: the hourly T1 roll-up now takes a coarse range's runs in key order and skips a job whose runs are all key-disjoint. A coarse range wider than one job (32 input runs) had the previous roll-up's output rewritten unmerged every hour, and gained about one run per cut range each hour. Its run and job counts now level off.
- bv-ct-index sidecar: a T1 compaction output run now closes once its key filter reaches 32,768 entries. A bigger run stored no filter, so every read in its range opened it.
- bv-ct-index sidecar: the coarse T0 -> T1 cut subset now picks cuts by a mixed hash. Keys that differ only near their end had put almost half the keyspace in one coarse range.

Ships with `npm run deploy:ct-index`, not `deploy:prod`.
