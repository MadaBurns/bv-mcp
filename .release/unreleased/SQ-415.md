### Added

- OAuth: Client ID Metadata Document (CIMD) clients. `/oauth/authorize` now accepts an https `client_id` URL such as Claude's `https://claude.ai/oauth/mcp-oauth-client-metadata` without Dynamic Client Registration. The document is fetched through `safeFetch` with no redirects, a 3 s timeout and a 5 KB cap. It must name itself as that exact `client_id`, describe a public client (no secret, `jwks` or non-`none` auth method) and list only allowlisted redirect URIs. Valid documents are cached for an hour, sealed when `KV_ENVELOPE_KEY` is set; failures are never cached. Loopback redirects (`localhost`, `127.0.0.1`) match with the port ignored (RFC 8252 section 7.3), so Claude Code's port-less registrations accept its ephemeral port. The consent page names a CIMD client by its `client_id` host rather than its self-asserted name. Authorization-server metadata advertises `client_id_metadata_document_supported: true`, and OAuth `client_id` inputs accept up to 512 characters (was 200). The bv-web customer grant path (`/internal/oauth/grants`) still resolves only registered clients until the follow-up grant change.
