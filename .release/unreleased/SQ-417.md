### Changed

- An unauthenticated `tools/call` to a paid-only tool now returns HTTP 401 with `WWW-Authenticate: Bearer resource_metadata="<issuer>/.well-known/oauth-protected-resource", scope="mcp"` instead of a bare 403, when OAuth is enabled and ready, so clients that start OAuth on a 401 (Claude's Connect card, Enterprise Managed Auth's silent exchange) can reach paid tools. The JSON-RPC body (`-32003` + `data.upgrade`) is unchanged; signed-in free/agent callers still get a plain 403, batch requests stay HTTP 200, and self-hosts without OAuth keep the 403. A rejected bearer on `/mcp` now also carries a `WWW-Authenticate: Bearer error="invalid_token", ...` challenge when OAuth is ready, and `WWW-Authenticate` is exposed through CORS.
