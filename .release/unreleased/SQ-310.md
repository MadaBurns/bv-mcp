### Fixed

- `check_subdomailing`: an SPF `include:` / `redirect=` target that contains an RFC 7208 §7 macro (`%{…}`, `%%`, `%_`, `%-`) is a template only a receiving MTA can expand, not a hostname. It is no longer probed as a literal name, no longer scored `void_include` ("which has no SPF record") and no longer spends a TXT lookup in the include walk (#1200, #1103). The probe returns a not-assessable result (`unmeasured: true`, `macroTemplate: true`, "cannot be resolved out-of-band and was not probed. This is not evidence that it is safe or unsafe."), the walk treats it as a childless leaf that still consumes one `MAX_INCLUDE_PROBES` slot (DFS cap semantics unchanged; parity spec green), the summary discloses `N macro-template include(s) not probed` with `macroTemplateCount` kept separate from `unmeasuredCount`, and when every include is a template or a thrown lookup the check abstains (`checkStatus: 'error'`, score 0, `partial`) instead of passing. New export `isSpfMacroTarget`.

Score impact (operator attention): a domain whose SPF chain contains a macro template beside literal includes loses a `low` `void_include` penalty it should never have had (`subdomailing` 95 → 100). A domain whose ONLY include is a macro template — the common Proofpoint hosted-SPF shape (`include:%{ir}.%{v}.%{d}.spf.has.pphosted.com`) — now has `subdomailing` EXCLUDED from the scan score (renormalised) rather than scored 95, and the result is `partial` (re-run each scan, one root TXT lookup). Package change in `@blackveil/dns-checks` (`checks/` only, no `scoring/` change): needs the dns-checks release and a bv-web-prod re-vendor to reach the published security reports.
